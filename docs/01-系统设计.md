# 智能桌台扫码点餐系统（Smart Table）系统设计文档

> 版本：v1.0 ｜ 日期：2026-08-26 ｜ 阶段：系统设计（开发前置）

---

## 1. 项目概述

### 1.1 项目目标

为线下餐厅提供一整套「桌面扫码 → 点餐 → 出餐」的数字化系统，面向真实营业场景使用：

- 顾客进店落座后扫描桌面二维码，免注册、免登录、免填写任何个人信息，直接点餐下单；
- 订单实时进入商家后台与厨房显示屏（KDS），全流程状态可追踪；
- 商家可通过后台完成菜品 / 分类 / 桌号 / 员工管理，并获得营业数据分析。

### 1.2 使用场景

```
顾客进店 → 落座 → 扫桌码 → 进入小程序（自动识别桌号，如 A08桌）
       → 浏览菜单/选规格 → 加购物车 → 提交订单
       → 商家后台实时收到新订单 → 接单 → 制作中 → 制作完成 → 已完成
```

### 1.3 系统角色

| 端 | 用户 | 核心能力 |
| --- | --- | --- |
| 顾客微信小程序 | 顾客 | 扫码进入、菜品浏览、分类、搜索、详情、购物车、下单、订单状态跟踪 |
| 商家后台（Admin Web） | 老板 / 店长 / 服务员 | 登录、实时订单、接单/改状态、菜品/分类/桌号/员工管理、经营数据分析 |
| 厨房订单系统（KDS） | 厨师 | 实时新订单展示、待制作/制作中/已完成状态流转 |

## 3. 技术选型

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 顾客小程序 | 微信原生小程序 + TypeScript | 启动快、扫码链路稳定、组件化清晰，符合真实营业要求 |
| 商家后台 / KDS 前端 | React 19 + TypeScript + Vite + React Router + Tailwind CSS | 生态成熟，KDS 与 Admin 共用组件库与鉴权 |
| 后端 | NestJS (Node.js + TypeScript) | 与前端同语言，模块化企业级框架；备选 Spring Boot 3/Java 21（如团队转向 Java 可按同一接口契约替换） |
| 数据库 | PostgreSQL 16 | 事务可靠，支撑订单状态机与统计查询 |
| 缓存 | Redis | 菜单缓存、订单号序列（INCR）、验证码 |
| 实时通信 | WebSocket（NestJS Gateway + socket.io 协议） | 房间隔离：merchant / kitchen / table:{code} |
| 文件存储 | 对象存储 OSS | 菜品图、桌台二维码 |
| 包管理 | pnpm workspace（Monorepo） | 统一依赖与脚本 |

## 5. 数据库设计（PostgreSQL）

> 金额单位统一为**分（integer）**；所有表含 `created_at / updated_at`。预留 `restaurant_id` 字段以支持未来 SaaS 多租户演进（v1 单店，值恒为 1）。

### 5.1 ER 关系

```
category 1 ─── n dish 1 ─── n dish_spec_group 1 ─── n dish_spec_option
dining_table 1 ─── n order_info 1 ─── n order_item
order_info 1 ─── n order_event（状态流转审计）
staff 1 ─── n order_info（经手人）
```

### 5.2 表结构 DDL

```sql
-- 员工账号（后台登录）
CREATE TABLE staff (
  id            BIGSERIAL PRIMARY KEY,
  restaurant_id BIGINT      NOT NULL DEFAULT 1,
  username      VARCHAR(32) NOT NULL UNIQUE,
  password_hash VARCHAR(128) NOT NULL,
  name          VARCHAR(32) NOT NULL,            -- 姓名
  role          VARCHAR(16) NOT NULL,            -- admin/manager/waiter/kitchen
  status        SMALLINT   NOT NULL DEFAULT 1,   -- 1 启用 0 禁用
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 桌号（二维码绑定）
CREATE TABLE dining_table (
  id            BIGSERIAL PRIMARY KEY,
  restaurant_id BIGINT      NOT NULL DEFAULT 1,
  code          VARCHAR(8)  NOT NULL UNIQUE,     -- A01 / B12
  area          VARCHAR(16) NOT NULL DEFAULT '大厅', -- 大厅/包间
  capacity      SMALLINT    NOT NULL DEFAULT 4,
  qr_code_url   VARCHAR(255),
  status        SMALLINT   NOT NULL DEFAULT 1,   -- 1 启用 0 停用
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 菜品分类
CREATE TABLE category (
  id            BIGSERIAL PRIMARY KEY,
  restaurant_id BIGINT       NOT NULL DEFAULT 1,
  name          VARCHAR(16)  NOT NULL,
  sort          INT         NOT NULL DEFAULT 0,
  status        SMALLINT    NOT NULL DEFAULT 1,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 菜品
CREATE TABLE dish (
  id            BIGSERIAL PRIMARY KEY,
  restaurant_id BIGINT       NOT NULL DEFAULT 1,
  category_id   BIGINT       NOT NULL REFERENCES category(id),
  name          VARCHAR(32)  NOT NULL,
  image_url     VARCHAR(255) NOT NULL,
  price         INT          NOT NULL,            -- 分
  description   VARCHAR(128),
  sales         INT          NOT NULL DEFAULT 0, -- 累计销量
  rating        NUMERIC(2,1) NOT NULL DEFAULT 4.5,
  status        SMALLINT    NOT NULL DEFAULT 1,  -- 1 在售 0 下架 2 售罄
  is_hot        BOOLEAN      NOT NULL DEFAULT false,
  is_signature  BOOLEAN      NOT NULL DEFAULT false,
  sort          INT         NOT NULL DEFAULT 0,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 规格组（如：份量 / 辣度）
CREATE TABLE dish_spec_group (
  id          BIGSERIAL PRIMARY KEY,
  dish_id     BIGINT      NOT NULL REFERENCES dish(id),
  name        VARCHAR(16) NOT NULL,
  required    BOOLEAN     NOT NULL DEFAULT true,
  sort        INT         NOT NULL DEFAULT 0
);

-- 规格选项（如：小份 -0 / 大份 +1000）
CREATE TABLE dish_spec_option (
  id          BIGSERIAL PRIMARY KEY,
  group_id    BIGINT      NOT NULL REFERENCES dish_spec_group(id),
  label       VARCHAR(16) NOT NULL,
  price_delta INT         NOT NULL DEFAULT 0    -- 分
);

-- 订单主表
CREATE TABLE order_info (
  id            BIGSERIAL PRIMARY KEY,
  order_no      VARCHAR(20) NOT NULL UNIQUE,     -- 20260826001
  restaurant_id BIGINT      NOT NULL DEFAULT 1,
  table_id      BIGINT      NOT NULL REFERENCES dining_table(id),
  table_code    VARCHAR(8)  NOT NULL,            -- 冗余快照
  status        VARCHAR(16) NOT NULL,            -- PENDING/ACCEPTED/COOKING/READY/COMPLETED/CANCELLED
  total_amount  INT         NOT NULL,            -- 分
  item_count    INT         NOT NULL,
  remark        VARCHAR(128),
  handler_id    BIGINT REFERENCES staff(id),     -- 经手员工
  cancel_reason VARCHAR(64),
  openid        VARCHAR(64),                    -- 匿名顾客标识（微信 openid）
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  accepted_at   TIMESTAMPTZ, cooking_at TIMESTAMPTZ,
  ready_at      TIMESTAMPTZ, completed_at TIMESTAMPTZ,
  cancelled_at  TIMESTAMPTZ,
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_order_status_created ON order_info(status, created_at DESC);
CREATE INDEX idx_order_table ON order_info(table_id, created_at DESC);

-- 订单明细（名称/价格快照，菜品后续修改不影响历史订单）
CREATE TABLE order_item (
  id          BIGSERIAL PRIMARY KEY,
  order_id    BIGINT       NOT NULL REFERENCES order_info(id),
  dish_id     BIGINT,
  dish_name   VARCHAR(32)  NOT NULL,
  image_url   VARCHAR(255),
  spec_text   VARCHAR(64),                      -- "大份 / 特辣"
  unit_price  INT          NOT NULL,             -- 分（含规格差价）
  quantity    INT          NOT NULL,
  subtotal    INT          NOT NULL
);

-- 订单状态流转审计
CREATE TABLE order_event (
  id          BIGSERIAL PRIMARY KEY,
  order_id    BIGINT      NOT NULL REFERENCES order_info(id),
  from_status VARCHAR(16),
  to_status   VARCHAR(16) NOT NULL,
  operator    VARCHAR(32),                      -- staff 姓名 / customer
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 5.3 订单状态枚举

| 状态 | 中文 | 触发方 |
| --- | --- | --- |
| PENDING | 待接单 | 顾客下单 |
| ACCEPTED | 已接单 | 商家 |
| COOKING | 制作中 | 商家/KDS |
| READY | 制作完成 | 商家/KDS |
| COMPLETED | 已完成 | 商家（顾客用餐结束） |
| CANCELLED | 已取消 | 顾客（仅 PENDING）/ 商家（需理由） |

## 6. 接口设计

### 6.1 通用约定

- 基础路径：`/api`；顾客端前缀 `/api/customer`，商家端前缀 `/api/admin`（JWT 鉴权）。
- 统一响应包：`{ code: 0, data: T, message: 'ok' }`；业务错误 `code != 0`。
- 下单幂等：`POST /orders` 携带客户端生成的 `clientToken`，后端去重防重复提交。
- 时间格式 ISO 8601；金额单位分。

### 6.2 顾客端接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /customer/restaurant | 餐厅信息（名称/公告/电话/营业时间） |
| GET | /customer/categories | 分类列表（含"热门推荐"虚拟分类） |
| GET | /customer/dishes?categoryId=&keyword= | 菜品列表（含规格组） |
| GET | /customer/dishes/:id | 菜品详情 |
| POST | /customer/orders | 提交订单 `{ tableCode, clientToken, remark, items:[{dishId, specOptionIds, quantity}] }` |
| GET | /customer/orders?tableCode= | 本桌当日订单 |
| GET | /customer/orders/:orderNo | 订单详情（含状态时间线） |
| POST | /customer/orders/:orderNo/cancel | 取消订单（仅待接单） |

### 6.3 商家后台接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /admin/auth/login | 登录，返回 JWT |
| GET | /admin/dashboard/summary | 今日营业额/订单数/客单价/热销前 5 |
| GET | /admin/orders?status=&page=&size=&date= | 订单分页查询 |
| POST | /admin/orders/:orderNo/accept | 接单 |
| POST | /admin/orders/:orderNo/status | 状态流转 `{ to }` |
| POST | /admin/orders/:orderNo/cancel | 取消 `{ reason }` |
| GET/POST/PUT/DELETE | /admin/dishes(/:id) | 菜品 CRUD |
| GET/POST/PUT/DELETE | /admin/categories(/:id) | 分类 CRUD |
| GET/POST/PUT/DELETE | /admin/tables(/:id) | 桌号 CRUD |
| POST | /admin/tables/:id/qrcode | 生成并上传桌码图片 |
| GET/POST/PUT/DELETE | /admin/staff(/:id) | 员工 CRUD |
| GET | /admin/stats/sales-trend?from=&to= | 营业额/订单趋势（按日） |
| GET | /admin/stats/dish-ranking?from=&to= | 菜品销量排行 |
| GET | /admin/stats/hourly?date= | 时段销售分析 |

### 6.4 WebSocket 事件

| 连接 | 房间 | 事件（服务端 → 客户端） |
| --- | --- | --- |
| /ws/customer?table=A08 | table:A08 | `order.status_changed` |
| /ws/merchant（JWT） | merchant | `order.new`、`order.status_changed`、`order.cancelled` |
| /ws/kitchen（JWT） | kitchen | `order.new`、`order.status_changed` |

心跳 25s；客户端断线指数退避重连，并携带 `lastEventId` 补拉缺失状态。

## 8. 核心业务流程

### 8.1 扫码进入流程

```
顾客扫桌码（小程序码 scene: table=A08）
  → 小程序冷启动 → app.onLaunch / index.onLoad 解析 scene（兼容 query 参数 table=A08）
  → 未携带桌码时默认进入 A08 桌（开发兜底，真实环境必经扫码）
  → 加载餐厅信息 + 分类 + 菜品（Redis 缓存 5 分钟）
```

### 8.2 下单时序

```
顾客                后端                    商家/KDS
 │ POST /orders     │                        │
 │ (幂等 token)     │ 校验桌号/菜品在售/价格   │
 │                  │ 生成订单号(Redis 序列)   │
 │                  │ 落库 PENDING            │
 │                  │── WebSocket order.new ─▶│ 铃声+高亮
 │◀─ 订单号/详情 ── │                        │
 │ 轮询/WS 跟踪状态  │◀── accept/cooking/ready ┤ 人工操作
 │◀─ status_changed ─│                        │
```

### 8.3 订单状态机

```
            ┌──────────── 顾客/商家取消（需理由） ────────────┐
            │                                              ▼
PENDING ──商家接单──▶ ACCEPTED ──开始制作──▶ COOKING ──出餐──▶ READY ──用餐结束──▶ COMPLETED
```

状态流转均写 `order_event` 审计表，任何非法跳转（如 PENDING→READY）由后端状态机校验拒绝。

### 8.4 异常流程

- **下单时菜品售罄/改价**：后端实时校验，返回最新价格由顾客确认后重提；
- **重复提交**：`clientToken` 幂等去重；
- **弱网断连**：小程序 5s 轮询兜底 + 重连补拉；
- **顾客取消**：仅 PENDING 可自助取消，其余需联系服务员（订单详情内置拨号）。

## 9. 安全与扩展设计

- 免登录信任边界：顾客端只读菜单+下单接口，写操作限流（同 IP/桌号），下单幂等；
- 二维码防伪造：小程序码由微信加密下发，scene 绑定桌号，后端校验桌号存在且启用；
- 商家端 RBAC：admin（全部）/ manager（订单+菜品）/ waiter（订单）/ kitchen（仅状态流转）；
- 多租户演进：全表预留 `restaurant_id`，后续增加租户路由中间件即可 SaaS 化。
